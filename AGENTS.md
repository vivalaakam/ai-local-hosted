# Инструкции для агентов

Этот файл — правила работы в репозитории `ai-local-hosted`. Продуктовый план и границы версий лежат в `PLAN.md`. Если план и этот файл расходятся в архитектуре, верным считается `PLAN.md`, а этот файл нужно поправить в том же изменении.

Пользователь пишет по-русски. Код, имена и коммиты — по-английски. Ответ пользователю — по-русски.

## Что это за продукт

Локальный Rust-сервер принимает запросы кодовых агентов и чат из GPUI-приложения. Он сам ходит в провайдера. У каждого пользователя свои чаты и свои провайдеры (`protocol`, `url`, `token`); пустую таблицу сервер не заполняет. Чаты хранит PostgreSQL. Десктоп хранит в SQLite адрес сервера, сессию входа, черновики и кэш списка. Десктоп не вызывает Ollama и не пишет секреты в keyring.

`references/` — чужие проекты для ориентира. Их не редактировать, не форматировать, не добавлять в workspace и не подключать как path-зависимости.

## Порядок работы

Фазы из `PLAN.md` идут по порядку: core, провайдер, Postgres, Chat Completions, API чатов, Responses и Anthropic Messages, GPUI, затем server tools. Не начинать десктоп, пока не зелёные фазы 4, 5 и 6. Перевод протоколов живёт в фазе 6 и в `alh-core`. Не встраивать его в фазу 4. Не добавлять RAG, память, failover и прочий бэклог внутри фазы, которая про другое. Серверные tools — отдельная фаза: не смешивать с пробросом клиентских tools в `/v1`.

Один шаг — один согласованный кусок. После него есть команда проверки из плана, и она запущена.

Новую зависимость не добавлять молча. Предложить крейт, зачем он, и дождаться согласия. Ставить через `cargo add`. После добавления запустить `cargo audit` и показать результат. Релизную сборку `--release` не делать.

Тулчейн серверных крейтов — stable Rust, edition 2024. Nightly не включать ради сервера. Если GPUI потребует nightly, pin только у десктопного тулчейна и написать об этом в `PLAN.md`.

## Границы крейтов

- `alh-core` — типы, ошибки, разбор `slug::model`, сбор контекста, трейт провайдера, перевод Anthropic Messages и Responses во внутренний запрос и обратно. Без axum, sqlx, sea-orm, reqwest, gpui, tokio-runtime в зависимостях. Асинхронные сигнатуры можно описать через `Future` и `Stream` из `futures`.
- `alh-providers` — HTTP к OpenAI-совместимому endpoint, разбор SSE. Без sqlx, sea-orm и gpui.
- `alh-storage` — миграции и репозитории на SeaORM. Без HTTP и gpui.
- `alh-tools` — каталог tools, native handlers, Rhai runtime и host `http_request`. Без axum, sea-orm и gpui. Может тянуть `reqwest` и `rhai`.
- `alh-server` — `apps/server`, axum, конфиг, склейка. Единственное место, где есть и база, и провайдер, и исполнение server tools в чате.
- `alh-desktop` — `apps/desktop`, окно, HTTP-клиент к нашему серверу, SQLite. Без `alh-providers`, `alh-storage` и `alh-tools`.

Провайдер не пишет в базу. Хранилище не знает URL Ollama. UI не собирает upstream-запрос. Пути `/v1/*` только пробрасывают клиентские tools; сервер их не исполняет. Цикл исполнения каталога tools крутится только в `POST /api/conversations/.../messages`. Rhai-скрипт объявляет `fn run(args)`; host даёт `http_request` / `json_parse` / `json_stringify`. Имена для модели: system `{slug}`, user `user__{slug}`.

## Контракты, которые легко сломать

Идентификатор модели — `qwen2.5-coder:7b` для дефолтного провайдера и `{uuid}::qwen2.5-coder:7b` для явного. `uuid` — id провайдера. Одинарное двоеточие не разделитель провайдера: это тег Ollama.

`POST /v1/chat/completions` стримит только при `stream: true`. Кадры — `data: {json}\n\n`, конец — `data: [DONE]\n\n`. Роли `system`, `user`, `assistant`, `tool` и поля `tool_calls` / `tool_call_id` проходят до upstream. Тело агентского запроса в `request_log` не сохраняется. В логе есть клиентская модель, upstream-модель, провайдер, статус, латентность и токены.

`POST /v1/messages` и `POST /v1/responses` не ходят в отдельную модель. Они переводятся в тот же `CompletionRequest`. Ответ клиенту остаётся в его протоколе. Поле модели в ответе повторяет имя из запроса. `claude-*`, `gpt-*`, `o1`, `o3`, `o4`, `codex-*` резолвятся в `default_model` по `config/model-aliases.toml`. Прочее неизвестное имя — `model_not_found`.

`/v1/messages` принимает и `Authorization: Bearer`, и `x-api-key`. Это access-токен пользователя, не общий секрет процесса. `/v1/responses` хранит транскрипт хода в `response_states` семь дней, включая запросы со `store: false`, потому что Codex продолжает ход через `previous_response_id`. В таблицу чатов этот транскрипт не пишется. Чужой `previous_response_id` для этого пользователя — `not_found`.

Чат: user-сообщение и пустой assistant со статусом `streaming` пишутся одной транзакцией до вызова модели. Дельты в базу не пишутся. Финал — одна запись. Если модель вернула `tool_calls` из серверного каталога, сервер исполняет их, дописывает assistant+tool сообщения и снова зовёт модель (лимит раундов). Закрытие HTTP обрывает upstream. Повторный стрим в разговор, где уже есть `streaming`, отклоняется. При старте сервера старые `streaming` становятся `error` / `interrupted`.

Ошибки клиенту — короткий код и сообщение. Сырой ответ провайдера в JSON клиенту не класть. В лог сервера его можно писать.

Секреты не коммитить. Общего `API_TOKEN` нет: вход — `POST /oauth/register` и `POST /oauth/token` (`grant_type=password` или `refresh_token`). Пароль на сервере хранится как argon2, в базе лежат только sha256-хеши токенов. Токен upstream хранится в `providers.token` и не попадает в JSON списка, ответы API и логи: снаружи только `has_token`. Протокол строки — `openai` или `anthropic` (`antropic` на входе приводится к `anthropic`). Вызов `anthropic` как upstream запрещён, пока нет отдельного адаптера. Сессия десктопа (access и refresh) лежит в SQLite, не в keyring. Токен провайдера в SQLite не писать.

## База

Локальный Postgres:

```text
postgres://local_user:local_password@localhost:15432/ai-local-hosted
```

Для запуска сервера обязателен только `DATABASE_URL`. Пример — `.env.example`. Бинарь читает `.env` через dotenvy и не затирает уже заданные переменные.

Доступ к Postgres — через SeaORM, без макросов `query!`, чтобы проверка компилировалась без живой базы. Миграции — SQL в `migrations/` и таблица `alh_migrations`. Уже накатанную `0001` не переписывать: если таблица `providers` есть, а версии нет, отметить `0001` применённой и накатить следующую.

Интеграционный тест, которому нужна база, живёт отдельно от `cargo test -p alh-core`. Он не делает `DROP DATABASE`, не чистит чужие таблицы и откатывает свои строки. Если переменная не задана, этот бинарь падает с понятным текстом, а не пропускает проверки молча.

## Десктоп

Десктоп лежит в `apps/desktop`. Сервер — источник сообщений. SQLite — `server_url`, сессия входа, черновики, кэш списка. Без сессии окно целиком показывает вход: URL, имя, пароль, Sign in и Create account. Узкая колонка слева — список чатов, New chat и Settings. Settings открывает отдельный экран в основной панели: URL сервера, выход, access-токен для агента, свой system prompt, список провайдеров и tools. Создание и правка провайдера — модальное окно, без поля id: сервер сам выдаёт UUID, человек задаёт имя. System tools только просмотр; свои Rhai tools — создать/править/удалить. Пресеты Ollama, Ollama Cloud и OpenCode подставляют адрес и протокол, остаётся токен; Custom просит адрес и протокол. В настройках Import Claude export читает zip, `conversations.json` или папку с такими файлами и пишет чаты в Postgres (`POST /api/imports/claude`). Повторный импорт тех же uuid пропускает уже сохранённые разговоры. Активная ветка берётся по `current_leaf_message_uuid`, иначе по последнему листу. Смена URL сбрасывает сессию. Токен провайдера в поле ввода не возвращать. Стрим рисуется батчами, а не на каждый токен. Stop рвёт запрос. Проверка фазы — сценарий из `PLAN.md`, не один скриншот. Keyring не использовать.

## Проверка

Серверные изменения:

```text
cargo fmt
cargo clippy --workspace --exclude alh-desktop --all-targets -- -D warnings
cargo test --workspace --exclude alh-desktop
```

Пока десктоп пустой и без gpui, `--exclude alh-desktop` можно убрать. После появления gpui серверная проверка остаётся без него, а `cargo test -p alh-desktop` идёт отдельно.

Не писать, что проверка прошла, если команда не запускалась. Если Postgres или Ollama не запущены, так и сказать: что зелёное, а что не гонялось.

## Чего не делать

- Не править `references/` и чужие `target/`.
- Не копировать AGPL-код «на время».
- Не тащить встроенный Postgres, Drizzle-схему LobeHub и роутер квот FreeLLMAPI. SeaORM используется только в `alh-storage`.
- Не хранить полный промпт агента.
- Не добавлять биллинг и эмбеддинги. Агентский цикл server tools — только в чате, не в `/v1`. Пользователи и парольный OAuth уже есть: не возвращать общий `API_TOKEN` и не переносить сессию десктопа обратно в keyring.
- Не вызывать API Anthropic или OpenAI Responses как upstream. Эти пути только вход клиентов. Upstream в первой поставке — OpenAI-совместимый провайдер, начиная с Ollama.
- Не прятать падение за `unwrap` на сетевом и базевом крае. Внутри чистых инвариантов core явный `expect` допустим, если нарушение означает баг программиста.
- Не оставлять комментарии, которые пересказывают следующую строку. Комментарий — только для неочевидного инварианта.
